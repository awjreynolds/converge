# Second provider selection for Converge

Status: recommendation for issue [#17](https://github.com/awjreynolds/converge/issues/17)

Researched: 2026-08-12

Decision: **implement Claude through the TypeScript Claude Agent SDK as Converge's second provider**

## Executive decision

Use `@anthropic-ai/claude-agent-sdk` behind a new provider-local transport and `AgentPort` adapter. It is the only evaluated option that currently documents all of the hard requirements together: validated JSON-Schema results, typed streaming events, local coding tools, durable session IDs and resume, cancellation, and a programmatic allow/deny callback for tool requests. The SDK is explicitly intended to expose the Claude Code agent loop from TypeScript, and its built-in tools read, write, and edit files, run commands, and search the web. ([Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview))

Do not select Gemini CLI for this issue. Its CLI and new TypeScript SDK are promising and cover local tools, streaming, resume, and cancellation, but the first-party SDK design currently marks approvals/policies and programmatic hooks as not implemented. Its documented agent options also expose no approval callback or caller-supplied result schema. Those are blocking gaps for Converge's separately mediated execution authority and structured phase contracts. ([Gemini SDK design/status](https://github.com/google-gemini/gemini-cli/blob/main/packages/sdk/SDK_DESIGN.md), [Gemini SDK options](https://github.com/google-gemini/gemini-cli/blob/main/packages/sdk/src/types.ts), [Gemini headless output contract](https://google-gemini.github.io/gemini-cli/docs/cli/headless.html))

This is a provider choice, not a model-quality judgment. Gemini should be reconsidered once its stable SDK has a documented programmatic approval surface and schema-constrained final results.

## Required fit

The issue requires an official local coding agent or agent SDK that can:

- produce machine-validated results for every Converge phase;
- stream safe progress without exposing hidden reasoning;
- edit a selected local workspace;
- persist and resume a provider conversation identity;
- cancel an active or starting turn;
- pause command, file, and network-capable tool use for a Converge decision;
- run headlessly from the VS Code Extension Host;
- leave credentials with the provider; and
- support a pinned compatibility policy and deterministic, offline tests.

The permission requirement is a gate. A provider that can edit autonomously but cannot hand a pending action to Converge for an explicit decision does not satisfy the ticket.

## Concrete Claude integration surface

Create a provider package such as `packages/claude` with three layers:

1. `ClaudeTransport`: the only layer that imports `@anthropic-ai/claude-agent-sdk`. It wraps `query()`, owns an `AbortController` for the current turn, captures `session_id`, and yields provider-local typed events. The SDK already models `query()` as an async message generator and exposes cancellation/session options. ([TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript), [sessions](https://code.claude.com/docs/en/agent-sdk/sessions))
2. `ClaudeAgentAdapter`: implements `AgentPort`, translates Converge phases to prompts plus phase-specific JSON Schemas, filters assistant text into concise progress, maps successful `structured_output` into domain events, and converts all provider failures into explicit normalized error events. Claude's structured output contract can fail after its validation retries or can report success without a structured value, so both cases must be rejected before any domain transition. ([structured-output failure behavior](https://code.claude.com/docs/en/agent-sdk/structured-outputs))
3. `ClaudeExecutionGate`: converts SDK tool requests into Converge's existing execution-approval event and awaits the UI decision. Use `permissionMode: "default"`, avoid bare `allowedTools` entries that bypass the callback, disable user/project/local settings with `settingSources: []`, and use a `PreToolUse` hook to force execution-affecting tools through the gate or deny unknown tools. Anthropic documents that settings can otherwise resolve a tool before `canUseTool`, while `PreToolUse` runs first. ([permission evaluation order](https://code.claude.com/docs/en/agent-sdk/permissions), [approval callback](https://code.claude.com/docs/en/agent-sdk/user-input))

Use one provider session across Converge phases. The first phase starts without `resume`; capture the earliest init/result session ID. Later phases call `query()` with `resume: storedAgentThreadId`. Persist `{ providerId: "claude", agentThreadId }` through the existing provider-neutral store, and refuse a provider mismatch. Claude stores the underlying transcript on provider-owned local disk and documents cross-process resume by ID. ([session capture and resume](https://code.claude.com/docs/en/agent-sdk/sessions))

Set `cwd` to the trusted VS Code workspace and expose only the tools needed by the current phase. Investigation can deny mutating tools. Implementation can expose editing and command tools but must still route every side-effecting request through the execution gate. Map WebFetch/WebSearch to an explicit network approval; if the host cannot present that request safely, deny it. Deny every unknown tool name. Claude documents both scoped tool deny rules and a deny-all wildcard. ([permissions and deny rules](https://code.claude.com/docs/en/agent-sdk/permissions))

Do not emit provider thinking blocks. Normalize only user-visible assistant text, tool lifecycle/progress, approvals, results, and errors. The Claude stream distinguishes partial stream events, complete assistant messages, and result messages, so this filter can live entirely inside the provider adapter. ([stream event model](https://code.claude.com/docs/en/agent-sdk/streaming-output))

## Security and test constraints

- **Credentials:** do not add an API-key setting, secret field, login UI, keychain entry, log field, or persisted auth state. Let the SDK subprocess use provider-owned environment/cloud authentication. Report only redacted authentication categories. Anthropic requires third-party Agent SDK products to use API-key or supported cloud-provider authentication rather than offering Claude.ai login. ([authentication rules](https://code.claude.com/docs/en/legal-and-compliance))
- **Repository content:** required CI must use a fake `ClaudeTransport` and checked-in synthetic protocol fixtures. It must never invoke a live provider or send the Converge repository, a user's repository, diffs, filenames, prompts, or transcripts externally.
- **Opt-in smoke test:** if added, a live test must require an explicit environment flag and human decision, create a synthetic disposable workspace containing no repository content or credentials, and remain outside required CI.
- **Workspace trust:** provider construction and every action-capable callback remain behind the existing VS Code trust boundary. The adapter's `cwd` must be the resolved trusted workspace, never an inferred parent or home directory.
- **Cancellation:** create the turn's `AbortController` before provider startup and retain a cancelled state so Stop during initialization aborts as soon as the SDK call exists. Exercise this through the shared `AgentPort` conformance seam.
- **Network:** a tool callback can mediate explicit web tools, but shell commands can contain implicit network behavior. Where network denial is promised, enforce it outside the model with a sandbox or egress proxy; Anthropic recommends proxy-enforced domain allowlists for hosted SDK deployments. ([network guidance](https://code.claude.com/docs/en/agent-sdk/hosting))

## Compatibility policy

Pin one exact `@anthropic-ai/claude-agent-sdk` version in the lockfile. Record that version as the adapter's supported protocol version, and update it only with:

1. provider-local fixtures for init, assistant/progress, tool approval, permission denial, structured success/failure, cancellation, disconnect, and resumed session;
2. the unchanged shared `AgentPort` conformance suite;
3. the provider-parameterized revoked-session walkthrough;
4. Extension Host provider selection and missing-auth/version diagnostics; and
5. a reviewed upstream changelog diff.

This follows Anthropic's documented model in which the SDK version pins its bundled CLI and minor updates should be reviewed. ([hosting/version guidance](https://code.claude.com/docs/en/agent-sdk/hosting))

## Explicit caveats

1. **Terms are not MIT.** Converge remains MIT, but using the optional Claude provider is additionally governed by Anthropic's Commercial Terms. Provider documentation must say so without implying that Converge relicenses Anthropic software. ([Anthropic terms](https://code.claude.com/docs/en/agent-sdk/overview))
2. **No Claude subscription login through Converge.** The integration must not broker or reuse consumer OAuth credentials. Users need an Anthropic Console API key or supported cloud-provider authentication suitable for third-party Agent SDK use. ([authentication rules](https://code.claude.com/docs/en/legal-and-compliance))
3. **The SDK is a subprocess architecture.** Each active query owns a CLI process and local transcript state; packaging must preserve the platform-specific optional dependency, and disposal must terminate the process. ([TypeScript installation/runtime](https://code.claude.com/docs/en/agent-sdk/typescript), [hosting architecture](https://code.claude.com/docs/en/agent-sdk/hosting))
4. **Permission callbacks are configuration-sensitive.** Auto-allow modes and bare allow rules can resolve tool calls before `canUseTool`. The adapter must control setting sources and enforce a first-stage hook rather than assume every call reaches the callback. ([permission evaluation](https://code.claude.com/docs/en/agent-sdk/permissions))
5. **Network control needs OS/container support.** A model tool boundary does not make arbitrary shell commands network-safe. Do not claim network denial without an enforced sandbox/egress mechanism. ([secure hosting guidance](https://code.claude.com/docs/en/agent-sdk/hosting))
6. **Session resume is not filesystem rollback.** Claude persists conversation history separately from workspace changes. Converge's immutable baselines and native VS Code diff workflow remain authoritative for code state. ([session semantics](https://code.claude.com/docs/en/agent-sdk/sessions))
7. **Experimental surfaces can be removed.** Build only on the documented `query()` API, not removed or experimental session APIs, and keep protocol drift isolated inside `packages/claude`. ([TypeScript V2 removal](https://code.claude.com/docs/en/agent-sdk/sessions))

## Reconsideration trigger for Gemini

Re-evaluate Gemini CLI as a later provider when a stable `@google/gemini-cli-sdk` release documents all three of the following: a caller-supplied JSON-Schema result contract, a programmatic pending approval callback with allow/deny responses, and stable hook/policy integration. Today the SDK design explicitly lists approvals/policies and hooks as missing, even though session resume, streaming, local tools, and `AbortSignal` cancellation are already implemented. ([SDK design/status](https://github.com/google-gemini/gemini-cli/blob/main/packages/sdk/SDK_DESIGN.md), [SDK session implementation](https://github.com/google-gemini/gemini-cli/blob/main/packages/sdk/src/session.ts), [SDK agent implementation](https://github.com/google-gemini/gemini-cli/blob/main/packages/sdk/src/agent.ts))
